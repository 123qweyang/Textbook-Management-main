# API 404 诊断方案

## 问题现象

前端页面打开后提示"网络请求错误,未找到该资源!"，对应 API 返回 HTTP 404。

## 请求链路

```
浏览器 → /jeecgboot/sys/permission/getUserPermissionByToken
  → nginx location /jeecgboot/ 
  → proxy_pass http://127.0.0.1:8080/jeecg-boot/sys/permission/getUserPermissionByToken
  → Spring Boot (port 8080, context-path=/jeecg-boot)
```

## 诊断步骤（在服务器 SSH 中顺序执行）

### 步骤1：确认后端是否健康

```bash
curl -v http://127.0.0.1:8080/jeecg-boot/sys/common/403
```

**预期**：返回 JSON（可能提示未授权，但不是 404 HTML）

**如果返回 Connection refused 或 404 HTML**：后端虽在运行但启动失败（MySQL/Redis 连接问题）

### 步骤2：查看后端启动日志

```bash
tail -100 /www/wwwroot/backend/nohup.out
# 或者看 logs 目录
ls /www/wwwroot/backend/logs/
tail -100 /www/wwwroot/backend/logs/spring.log
```

关键检查：是否有 `Failed to configure a DataSource` 或 `Unable to connect to Redis` 错误。

### 步骤3：确认 MySQL 和 Redis 是否运行

```bash
# MySQL
systemctl status mysql 2>/dev/null || systemctl status mysqld 2>/dev/null

# Redis（后端 prod 配置需要密码 111111）
redis-cli -a 111111 ping
```

### 步骤4：确认 nginx 配置生效

```bash
# 检查 nginx 配置是否真用了 proxy_pass
nginx -T 2>/dev/null | grep -A 10 "location.*jeecgboot"
```

## 根据日志判断

| 日志关键词 | 原因 | 解决 |
|-----------|------|------|
| `Connection refused` 或 `Failed to configure a DataSource` | MySQL 未运行或密码错误 | 启动 MySQL 或改密码 |
| `Unable to connect to Redis` | Redis 未运行或密码错误 | 启动 Redis 或改密码 |
| `curl :8080` 返回正常 JSON 但 nginx 代理返回 404 | nginx 配置未生效 | `nginx -s reload` |
| `curl :8080` 返回 404 HTML 页面 | 后端 war/jar 启动但 Spring 容器未加载 | 看步骤2日志 |

> **把步骤1和步骤2的输出发给我，直接定位根因。**
