# "网络请求错误,未找到该资源!" 诊断方案

## 错误触发点

`src/utils/http/axios/checkStatus.ts` 第 39-40 行：当 API 请求返回 HTTP 404 时显示。

## 前端请求链路

1. `.env.production` 中 `VITE_GLOB_API_URL=/jeecgboot`
2. 前端构建后所有 API 请求前缀为 `/jeecgboot/`
3. 例如：`GET /jeecgboot/sys/permission/getUserPermissionByToken`
4. Nginx `proxy_pass http://127.0.0.1:8080/jeecg-boot/` 将请求转发到后端
5. 后端返回 404 → 前端弹窗 "网络请求错误,未找到该资源!"

## 诊断步骤（在服务器 SSH 执行）

```bash
# 1. 检查后端是否在运行
ps aux | grep java | grep -v grep
# 或者
ss -tlnp | grep 8080
```

```bash
# 2. 直接测试后端接口
curl http://127.0.0.1:8080/jeecg-boot/sys/permission/getUserPermissionByToken
# 正常应返回 JSON（可能是 "未登录" 的响应，但不是 404 页面）
```

```bash
# 3. 测试 nginx 代理
curl http://127.0.0.1/jeecgboot/sys/permission/getUserPermissionByToken
# 同样应返回后端 JSON
```

```bash
# 4. 查看 nginx 错误日志
tail -20 /www/wwwlogs/118.31.226.56.error.log
```

## 根据结果判断

| 现象 | 原因 | 解决 |
|------|------|------|
| `ps` 没有 java 进程 | 后端未启动 | 启动 Spring Boot 服务 |
| `curl :8080` 返回 `Connection refused` | 后端未启动或端口不对 | 检查后端配置文件中的端口 |
| `curl :8080` 正常但 `curl nginx` 返回 404 | nginx proxy 配置有问题 | 检查 `/jeecgboot/` location 配置 |
| `curl :8080` 返回 404 HTML 页面 | 后端启动了但 context-path 不对 | 后端配置 `server.servlet.context-path=/jeecg-boot` |

> **把上面 4 条命令的输出发给我，直接定位。**
