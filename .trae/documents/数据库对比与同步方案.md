# 数据库对比与同步方案

## 对比结果摘要

| 对比维度 | SQL 文件（原始） | 本地数据库 | 结论 |
|---------|-----------------|-----------|------|
| 表数量 | 131 张 | 131 张 | ✅ 完全一致 |
| 视图数量 | 0 个 | 7 个 | 本地多了 7 个应用视图 |
| 表结构 | — | — | 仅 1 张表有差异（见下） |
| 数据行数 | 初始种子数据 | 大量业务数据 | ⚠️ 显著不同 |

## 一、表结构差异

### 唯一差异：`student_bill` 表

| 位置 | 列数 | 差异 |
|------|------|------|
| SQL 文件 | 13 列 | `id, student_id, major_name, subscription_year, subscription_semester, textbook_name, price, discount_price, subscribe_status, receive_status, remark, create_time, update_time` |
| 本地 | 17 列 | 多了 `class_name`, `college_name`, `isbn`, `student_id` 后有 `major_name` 前有排列差异 |

这说明本地数据库在开发过程中对 `student_bill` 表做了字段扩展。

### 其他 130 张表

经过逐表对比，其余 130 张表的列定义（列名、类型、默认值、是否可空）**完全一致**。之前报告中显示的"类型差异"均为 COMMENT 注解和 CHARACTER SET 声明方式的差异，不影响实际表结构。

## 三、同步方案

### ⚠️ 重要前置步骤：备份本地数据库

在执行任何同步操作前，务必先备份：

```powershell
mysqldump -uroot -p123456 --routines --triggers --events jeecg-boot > jeecg-boot_backup_20260714.sql
```

### 方案一：完全替换（推荐用于重置环境）

**适用场景**：需要将数据库完全重置为初始状态（所有业务数据将被清空）。

```powershell
mysql -uroot -p123456 jeecg-boot < jeecg-boot.sql
```

**影响**：
- ✅ 所有表结构和数据恢复为原始状态
- ✅ 视图不受影响（SQL 文件中无 DROP VIEW）
- ❌ 本地所有业务数据（学生、征订、领取等）将全部丢失
- ❌ `student_bill` 表将失去 `class_name`、`college_name`、`isbn` 三个字段

### 方案二：仅同步系统基础数据（保留业务数据）

**适用场景**：只想重置系统配置表（用户/角色/权限/字典等），保留教材管理业务数据。

```sql
-- 1. 禁用外键检查
SET FOREIGN_KEY_CHECKS = 0;

-- 2. 清空并导入系统基础表（从 SQL 文件中提取对应 INSERT 语句执行）
-- 注意：以下为示意，需从 jeecg-boot.sql 中提取实际 INSERT 语句

-- 系统表（建议同步）
-- sys_user, sys_role, sys_role_permission, sys_user_role
-- sys_permission, sys_role_index
-- sys_dict, sys_dict_item
-- sys_depart, sys_depart_role, sys_depart_permission, sys_depart_role_user, sys_depart_role_permission
-- sys_announcement, sys_announcement_send
-- sys_category, sys_check_rule, sys_data_log, sys_data_source
-- sys_fill_rule, sys_form_file, sys_gateway_route, sys_log
-- sys_position, sys_quartz_job, sys_sms, sys_sms_template
-- sys_table_white_list, sys_tenant, sys_tenant_pack, sys_tenant_pack_perms, sys_tenant_pack_user
-- sys_third_account, sys_third_app_config
-- sys_user_dep_post, sys_user_depart, sys_user_position, sys_user_tenant

-- 3. 恢复外键检查
SET FOREIGN_KEY_CHECKS = 1;
```

### 方案三：按需部分同步（最灵活）

**适用场景**：只同步特定几张表。

例如只想更新教材数据（原始有 768 本，本地只有 453 本）：

```sql
-- 1. 备份现有数据
CREATE TABLE t_textbook_backup AS SELECT * FROM t_textbook;

-- 2. 清空并重新导入（从 SQL 文件提取 INSERT INTO t_textbook 语句执行）
DELETE FROM t_textbook;
-- 然后执行 SQL 文件中的 INSERT INTO t_textbook ... 语句

-- 如果需要回滚
-- INSERT INTO t_textbook SELECT * FROM t_textbook_backup;
```

### 推荐操作

| 你的目标 | 推荐方案 |
|---------|---------|
| 完全重置为项目初始状态 | 方案一 |
| 重置系统配置但保留业务数据 | 方案二（需手动从 SQL 文件提取 INSERT） |
| 只更新某几张表的数据 | 方案三 |

## 四、关于本地视图

本地数据库有 7 个视图（SQL 文件中不存在），它们是应用程序运行时创建的：

- `v_class_with_counselor`
- `v_receive_with_details`
- `v_student_bill_summary`
- `v_student_bill_with_isbn`
- `v_student_with_counselor`
- `v_subscription_with_details`
- `v_textbook_selection_with_isbn`

执行方案一不会影响这些视图（SQL 文件中没有 DROP VIEW 语句）。但如果执行后视图失效，可通过应用重新创建。

## 五、student_bill 表结构差异处理

如果选择方案一（完全替换），`student_bill` 会恢复到 SQL 文件的 13 列结构。
如果后续需要恢复本地扩展的 4 个字段，执行：

```sql
ALTER TABLE student_bill 
  ADD COLUMN class_name VARCHAR(50) NULL DEFAULT '' COMMENT '班级名称' AFTER student_id,
  ADD COLUMN college_name VARCHAR(50) NULL DEFAULT '' COMMENT '学院名称' AFTER class_name,
  ADD COLUMN isbn VARCHAR(50) NULL COMMENT '教材ISBN' AFTER discount_price;
```
